# ADR 0001: Монорепо на Turborepo + pnpm

**Дата:** 2026-04-18
**Статус:** принято

## Контекст

Проект состоит минимум из трёх приложений (web, admin, api) и нескольких общих пакетов (типы, UI, Prisma-клиент). Нужно избежать дублирования кода и переключения между репозиториями.

## Решение

Монорепо: **Turborepo + pnpm workspaces**.

## Причины

- pnpm workspaces — эффективное управление зависимостями, жёсткие ссылки между пакетами.
- Turborepo — кеш сборок (локально и в CI), параллельный запуск задач, понятная конфигурация.
- Общие типы (`packages/types`) автоматически синхронизируются между фронтом и бэком — изменил DTO → все проекты увидели.
- Легко добавлять новые приложения (мобильное, лендинг) без раздувания одного репозитория.

## Альтернативы

- **Nx** — мощнее, но сложнее, избыточен для текущего масштаба.
- **Отдельные репозитории** — синхронизация типов превращается в ад.
- **Один Next.js проект** — невозможно разделить бэкенд-логику при росте.
